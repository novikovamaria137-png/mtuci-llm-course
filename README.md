# Практика 2.1. Рабочее окружение LLM-разработчика

Модуль 2 «Разработка приложений с LLM» · урок 1 · 110 минут практики.

Ноутбук собирает каркас проекта `llmcourse`, который дополняется на всех десяти
уроках модуля. К уроку 2.2 у слушателя должна быть рабочая папка из шага 2.

---

## Как выложить практику слушателям

1. Создайте публичный репозиторий на GitHub, например `novikovamaria137-png/mtuci-llm-course`.
2. Положите туда содержимое этой папки по такому пути:

   ```
   lesson-2.1/practice.ipynb
   ```

3. В первой ячейке ноутбука замените `novikovamaria137-png/mtuci-llm-course` на реальное имя
   репозитория — от него зависит адрес в кнопке «Открыть в Colab».
4. Проверьте, что кнопка открывает ноутбук. Адрес формируется так:

   ```
   https://colab.research.google.com/github/<владелец>/<репозиторий>/blob/main/lesson-2.1/practice.ipynb
   ```

Если репозитория пока нет, ноутбук можно раздать файлом: Colab открывает
`.ipynb` через «Файл → Загрузить блокнот». Кнопка при этом работать не будет,
на содержание практики это не влияет.

## Что лежит в папке

| Файл | Назначение |
|---|---|
| `practice.ipynb` | ноутбук практики, 23 ячейки, шаги 0–8 |
| `llmcourse/config.py` | поиск ключа: Colab Secrets → переменные окружения → `.env` |
| `llmcourse/client.py` | обращение к модели, повтор с выдержкой, учёт расхода |
| `requirements.txt` | зафиксированные версии библиотек |
| `.env.example` | шаблон настроек без значений |
| `.gitignore` | защита от попадания `.env` в репозиторий |

Файлы `llmcourse/config.py` и `llmcourse/client.py` **слушатель создаёт сам** —
ноутбук записывает их ячейками `%%writefile`. Здесь они приложены как эталон:
чтобы преподаватель мог сверить результат и чтобы код было видно без запуска.

## Что проверено и что нет

Проверено фактическим запуском 30.07.2026 (Python 3.10.12, Linux aarch64,
`openai==2.51.0`, `python-dotenv==1.2.2`):

- все 11 ячеек с кодом выполняются без ошибок с чистого листа;
- шесть самопроверок каркаса проходят: детерминированность заглушки, оценка
  токенов, расчёт стоимости, различение повторяемых и неповторяемых ошибок,
  восстановление после двух сбоёв подряд, единственная попытка при коде 400;
- детектор утечек срабатывает на подставном файле с фальшивым ключом;
- клиент собирается на библиотеке `openai` версии 2.51.0, параметры
  `messages`, `model`, `temperature`, `max_tokens` и классы ошибок
  `RateLimitError`, `APITimeoutError`, `APIConnectionError`,
  `InternalServerError`, `BadRequestError` в ней присутствуют.

**Не проверено:** шаги 6 и 7 с действующим ключом. Среда сборки материалов не
имеет доступа к API поставщиков, поэтому реальное обращение к модели, формат
поля `usage` у конкретного поставщика и поведение при частичной совместимости
автором не наблюдались. В ноутбуке эти ячейки помечены строкой
«требует проверки на живом ключе».

**Перед запуском потока** эти два шага нужно пройти на реальном ключе того
поставщика, которого выбрал вуз, и при расхождении поправить ноутбук.

## Ключи доступа

Ноутбук работает без ключа: при его отсутствии клиент переходит в автономный
режим и возвращает детерминированную заглушку. Шаги 0–5 и 8 выполняются
полностью, шаги 6–7 требуют доступа.

Три места, откуда берётся ключ (в этом порядке):

1. **Colab Secrets** — значок ключа на левой панели Colab. Значение хранится
   в аккаунте и не попадает в файл ноутбука при его отправке другому человеку.
2. **Переменные окружения** — для сервера и CI.
3. **Файл `.env`** — для локальной работы. В репозиторий не попадает.

Имена переменных: `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.

Если ключ всё же утёк — **сначала отзовите его в панели поставщика**, и только
потом чистите репозиторий. Удаление коммита не помогает: ключ остаётся
в истории.

## Локальный запуск без Colab

```bash
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # и вписать свои значения
jupyter notebook practice.ipynb
```

Требуется Python 3.9 или новее — ноутбук проверяет это в шаге 0.
